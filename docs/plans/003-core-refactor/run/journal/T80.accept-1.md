## Найденный дефект: тип instance в EventEmitter не связан с transport

Адрес: __temp/plan-core-refactor/types/generic.d.ts:25 (Options.eventHandler) и docs/plans/003-core-refactor/evidence/fetch-contract.md:56. Исследование утверждает проведение одного F до eventHandler/instance и рекомендует EventEmitter<EventMap<F>>, но не выявляет несовместимый emitter. Настоящий EventEmitter с native EventMap принимается constructor undici-планировщика; listener при этом видит FetchPlanner<NativeFetch> и Promise<global Response>, включая bytes(). Прямой getFetch того же экземпляра честно даёт старый undici Response без bytes. Никакого cast/any/suppression в fixture нет. Неверная аннотация emitter — обычная проверяемая ошибка потребителя; она отличается от правильного native emitter из штатного positive fixture.

Воспроизводимый fixture (bare24; тот же generic.d.ts как contract.d.ts):

```ts
import { FetchPlanner } from './contract.js'
import type { FetchPlannerEventMap } from './contract.js'
import { EventEmitter } from 'node:events'
import type { fetch as uf } from 'undici-types'
declare const undiciFetch: typeof uf
const nativeEvents = new EventEmitter<FetchPlannerEventMap<typeof globalThis.fetch>>()
nativeEvents.on('request', (event, planner) => {
  const nativeResponse: Promise<Response> = planner.getFetch()(event.url)
  void nativeResponse.then(response => response.bytes())
})
new FetchPlanner(undiciFetch, { eventHandler: nativeEvents })
```

## Остальные критерии и края

- Generic и отдельные native/undici overloads реально компилировались обоими компиляторами на одинаковых consumers. Generic native-basic, legacy, custom, subclass проходят в обеих Node-type средах; полные native bytes проходят только с Node24 types. На Node22 обе альтернативы дают ровно две TS2339 для Request/Response.bytes. Old contract остаётся красным даже после смены @types/node. Обоснование уточнения типов подтверждено; оно не заменяет исправление Fetch-сигнатуры.

- Constructor/getFetch/wrapFetch/RequestEvent проверены; native Request/URL/FormData/File-body, Promise<Response> и bytes сохраняются, direct undici-types7.3.0 не заменён. Legacy installed undici и bare declaration transport сохраняют Response без bytes. Overloads теряют custom return/trace и protected subclass — ожидаемые отдельные красные пробы.

- Отрицательные transport/constructor/input/body/method/event/union/callable-property пробы проверяются runner по числу, точной исходной строке и TS-коду, не просто exit1. Нормализованный callable не обещает marker исходной функции. Union результат остаётся Promise<Response | legacy Response>, а union input не разрешает чужой undici Request произвольно выбранному transport.

- В дополнительных 28 пробах проверены custom undici Response/Init, default legacy class annotation, безопасный union string/URL, response/fetch-error event listeners и event instance. Cross-family undici Request → native отвергнут; обратное native Request → legacy проходит структурно на обеих Node-type версиях — это не доказательство взаимозаменяемости и не дефект, поскольку native Request имеет достаточные поля для старого undici Request. Неверный union result Promise<global Response> отвергается ровно одной TS2322.

- Missing-dependency mutation выполнялась в своей копии: реальный declaration import undici-types заменён на undici в bare24, обе версии compiler выдали ровно одну TS2307 из contract.d.ts; после пробы копия возвращена. Других намеренных мутаций production не было.

- Запрещённых cast/any/ts-ignore/skipLibCheck:true в исследовательских consumers не обнаружено; vendor declarations не переписывались. Declarations bytes сверены напрямую: nested undici-types7.24.6/fetch.d.ts:36 содержит bytes, direct7.3.0 BodyMixin — нет.

- Точные имеющиеся fixtures и runner доступны для T90 в текущем прогоне; временное размещение само по себе не блокер по брифу. Для package gates перечислены сохранение bare closure, negative diagnostics, root/deep, tarball и smoke; тест настоящего tarball остаётся T90. Непараметризованные event/class defaults и ограничение произвольных generic/overloaded callable описаны как breaking-уточнения. Не хватает только обнаруженной event-handler границы.
