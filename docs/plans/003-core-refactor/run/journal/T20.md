## Реализация и green

`src/pacing.ts` содержит внутренние чистые функции округления положительных опций, таблицы101 шага, формулы задержки и проверки временной арифметики. Входы времени/random передаются значениями; коэффициенты/defaults и порядок вычисления jitter сохранены. Нормализованная доля ограничена сверху1, отрицательное elapsed после отката часов ограничено0; исходные remaining не переписываются. Небезопасные delay/deadline дают явную ошибку. Период correction сохраняет прежнюю формулу; проверена также безопасность умножения периода на jitter и результирующего времени, correction clamp не реализован.

`src/response-policy.ts` принимает только status и объект чтения headers, не queue/planner/body. Missing возвращает null для «не обновлять». Сохранён Number.parseInt без нового строгого формата: 7ms →7. После разбора требуется safe integer с Limit>0, Remaining>=0, Retry-TimeInterval>0, Retry-After>=0. Legacy x-lognex-auth429005 классифицируется как PARALLEL_LIMIT_OVERFLOW, прочий429 — RATE_LIMIT_OVERFLOW, все non429 включая4xx/5xx — OK. Retry-After читается только для rate429, как прежде;0 не заменяется fallback. Reset/JSON1073/backoff не добавлены. Все заголовки разбираются до применения результата и до retry/requeue, поэтому ошибка parsing не оставляет частичного обновления headers/очереди; это следствие чистой policy, не решение общего lifecycle.

`src/index.ts` подключает обе policy, сохраняет getters/protected поля и hook. getOptions по-прежнему возвращает тот же изменяемый объект; комментарий прямо говорит, что mutation не является поддержанным конфигурированием и не обновляет таблицу. Нестандартные/нечисловые значения numeric options отклоняются синхронно;0.1 отвергается,0.6 округляется1. Correction period применяется после округления к безопасному целому>=1000, max delay>=1; jitter допускает дробные[0,0.3], coefficient[1,20]. Длительности2147483647/2147483648 и MAX_SAFE_INTEGER не обрезаются конструктором до int32. Чужой блок errorLimits interface/defaults сохранён без изменений семантики, counters/guard отсутствуют.

Тесты дополняют T10 и прежние сценарии: независимое вычисление формулы (не через production table) для remaining0/1/25/49/50/99/100/101/MAX_SAFE_INTEGER, elapsed0/4/5/100/499/1000/1001, coefficient1/2.5/5/20, jitter0/0.1/0.3 и random0/0.5/1. Для каждого из4 headers отдельно проверены missing,0,-1,7,7ms,NaN,Infinity,-Infinity,unsafe integer, полностью invalid/пустое значение и MAX_SAFE_INTEGER. Проверены partial/missing state, remaining>limit, ошибки deadline, сохранение non429 Response identity и OK events, отсутствие мутации pending queue при вызове чистого parser. Numeric options проверены на нечисловых входах,0/отрицательных/0.1/NaN/±Infinity/unsafe integers, минимуме и округлении снизу, int32 границах; defaults и mutable getOptions проверены отдельно.
