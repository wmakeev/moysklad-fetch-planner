## Исполняемые сценарии

`test/fetch-contract.test.ts` явно подключён в package.json test:unit: семь новых тестов; сохранены все 98 прежних. Native/undici Request metadata; undici fake проверяет identity URL/init/body/signal/Response для string, Buffer, FormData, File и stream; signal обслуживает transport, его rejection даёт один fetch-error без retry и оставляет queue/inflight0; string/Buffer на429 повторяются дважды с теми же init/body. Для fake timers два последовательных advance0 выполняют первый admission и admission retry.

`test/package/fixtures/runtime.mjs` сохраняет исходные root/deep import и fake GET/POST smoke, добавляет настоящий native fetch на 127.0.0.1. Проверены URL, POST Request, PUT/body override из init, string без init, string/Buffer/FormData с текстовым и File полями/File/ReadableStream payload по содержимому, исходный Response с непрочитанным body, HTTP404/503 как responseType OK. String/Buffer после429 дают два одинаковых содержимых на сервере. Server/connections закрываются в finally.

Там же шесть конечных one-shot сценариев: Request/stream после429 отвергаются на второй попытке, уже disturbed и locked Request/stream отвергаются на первой. Сохранены identity входного Request/stream и исходная transport error; проверены один fetch-error, один settlement, queue/inflight0 и успешный следующий запрос тем же planner. Захваченный reader освобождается в finally. Unit suite исполняет этот fixture отдельным child с `--unhandled-rejections=strict`: exit0, stderr пустой, естественное завершение; watchdog10000мс только проваливает зависший тест, без process.exit/unref/private cleanup. Пакетный runner исполняет тот же fixture из настоящего tarball в bare и undici consumers.
