## Краевые пути и соответствие T40

- Shared pause/success и enqueue: текущий scheduler suite действительно запускает два запроса, получает 429 и проверяет отсутствие третьего старта на receipt+399, разрешение на receipt+400. Нельзя выдать отсутствие импорта за red: baseline компилируется и падает именно по starts 3/4 вместо 2. Независимый replay совпал с конкретным утверждением журнала T40.md [VERIFY].
- Собственные interleaving пробы используют другую временную шкалу: receipt первого 429 в75мс, второго в200мс, hints400 и100/600. Проверены абсолютные границы475/800, callback enqueue из response, ещё один enqueue, максимум двух абсолютных deadline, запрещённый старт за1мс до границы и разрешённый на самой границе.
- Поздний успешный ответ с полным remaining и response callback enqueue проверены scheduler suite: ни late headers, ни соседний success/finally не уменьшают400мс. Повторное планирование через enqueue и completion проходит через один pump.
- Устаревший callback принудительно вызван при действующей паузе и после drain: новых actions не стартует. Максимум активных scheduling timeout равен1, после drain0. Пустая очередь после terminal response observer error не удерживает timeout; следующий enqueue сохраняет остаток server deadline.
- Собственные независимые пробы скачков wall clock на+100000000/-200000000 при фиксированном monotonic проверяют пересчёт Unix getter; отдельные pacing пробы на+10000000/-10000000 подтверждают сохранение1000мс pacing при server boundary400 и enqueue в250мс. В scheduler suite проверены ещё wall jumps+10000000/-900000. При отсутствии wake getter возвращает0.
- Длинные deadlines2147483647/2147483648 проверены штатным suite по исходному первому bounded chunk. Дополнительно самостоятельно проверены эти границы и4294967300мс, enqueue внутри паузы, wall rollback и несколько chunks. За1мс до полного deadline starts остаётся1; на границе стартуют retry и новый action. Все delay<=2147483647, TimeoutOverflowWarning отсутствует, активный таймер один, после drain таймеров нет. Реального ожидания длинного интервала нет.
- FIFO сохранён в согласованном смысле retry unshift: после двух ответов429 retry последнего ответившего идёт раньше первого, затем обычные queued actions c/d. Методы getOptions и фасад не изменены; по diff сохранена mutable семантика и незавершённая errorLimits. Новый публичный runtime adapter не добавлен.
- Полные check/coverage включают все T10–T40 suites; проходят strict child lifecycle, reentrant request/response/fetch-error, observer throw, late response/rejection, естественное завершение child. Новых skip/todo/only нет. Расширенный harness не отключает проверки T10; его тесты продвижения часов и восстановления globals зелёные.
- Сравнение git diff с HEAD показывает ровно три согласованных старых теста в test/index.test.ts.
