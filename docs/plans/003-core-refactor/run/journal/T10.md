# T10 — управляемый offline harness и стабильный jitter

Полностью прочитаны бриф, контекст, план и исследование F02/F08/F10/A6. Навык moysklad-api и открытый feedback прочитаны; серверная политика не меняется. Исходный diff собственных файлов пуст, кроме чужой errorLimits в src/index.ts; src не правится. Проверены /proc/<pid>/cwd и cmdline процессов данного checkout: только браузерные MCP, читателей test-build нет. Фактические pinned версии: Node24.22.2/pnpm12.16.1/TS7.0.2.

Все команды ниже используют PATH из плана и timeout 300; полный stdout/stderr сохраняется ниже. Только offline fake transport, без .env/live/stress/аккаунтов и внешних записей. Карта прогона не меняется.

[ALT, SURFACE, CONSIST] Выбран test-only harness на контекстных node:test mocks: совместные Date/setTimeout/setInterval, управляемый Math.random и event-loop barrier через настоящий setImmediate для promise chains. Альтернатива — внутренний production adapter времени/random; он не нужен, поскольку текущий interval time вычисляется через Date.now, и раздувает поверхность решения. Production/public API и политика остаются прежними. advance продвигает время явными шагами, flush не исполняет будущие timers; это не симулятор событий с автоматическим выбором следующего deadline.

Контрольный test целиком удалён перед финальной зелёной проверкой; production политика не затронута.
