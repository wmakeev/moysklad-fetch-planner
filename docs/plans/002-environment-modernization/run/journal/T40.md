## Исходное состояние и решение

До запуска старых test/coverage прочитаны package.json, test/stress.test.ts, test/index.test.ts, конфигурации TypeScript/ESLint и локальные README/реализация c8. Старые test/coverage не запускались: coverage использовал `node -r dotenv/config --test` без явного entrypoint, а stress entrypoint создавал Piscina без guard. Исходные 13 тестов используют undici MockAgent с disableNetConnect().

`test` собирает test build и вызывает `test:unit`; единственный список offline entrypoints находится в `test:unit`: `node --test --enable-source-maps __temp/test-build/test/index.test.js`. `coverage` собирает тот же test build, измеряет `c8 pnpm run test:unit` и обязательно запускает coverage:check. Это сохраняет один список тестов для обоих путей [CONSIST]. dotenv в этих командах отсутствует. `test:unit` предназначен для уже собранного test build; самостоятельная команда с компиляцией — `test`.

Конфигурация c8 включает исполняемый `__temp/test-build/src/**/*.js` и отображённый по source maps `src/**/*.ts`, с exclude-after-remap=true. Измерение production build не используется; R01 закрыто проверкой raw V8 URLs и LCOV, а не только exit code.

Добавлен scripts/check-coverage.mjs: coverage/coverage:report не принимают отчёт без src/index.ts, положительных DA/FNDA и отдельного положительного FNDA wrapFetch. Все SF должны указывать на исходные src/*.ts; test/samples и compiled paths отвергаются. Порог покрытия не повышался, новые unit assertions ради процентов не добавлялись.

`test:live` запускает отдельно compiled stress entrypoint. Внутри entrypoint до динамического импорта Piscina проверяется `MOYSKLAD_LIVE_STRESS === '1'`, иначе выбрасывается понятная ошибка `Live stress is disabled. Set MOYSKLAD_LIVE_STRESS=1 explicitly and supply credentials externally to enable live requests.` Credentials остаются внешним вводом; dotenv не добавлен. Guard защищает также прямой импорт compiled entrypoint. Альтернатива — внешний scripts/run-live.mjs; она не нужна, поскольку внутренний guard уже закрывает оба пути и не добавляет второй механизм [ALT, SURFACE, ROOT]. Реальный opt-in не проверялся.

## Среда и безопасность проверки

Все итоговые проверки выполнены на Node v24.22.2 из `__temp/environment-compat/node_modules/node/bin` и pnpm 12.16.1; TypeScript 5.7.3. Установленная версия c8 подтверждена manifest node_modules/c8/package.json: 12.0.0. Глобальный node v24.16.0 для приёмки не использовался.

Основной проверочный runner — `/tmp/orchestrate-fetch-planner-002/T40-1/verify.py`. Он создаёт окружение subprocess из HOME/USER/LANG/TMPDIR и PATH, не передаёт остальные переменные и секреты; MOYSKLAD_TOKEN/MOYSKLAD_LIVE_STRESS явно отсутствуют и это проверяется preload. Каждая проверяемая команда обёрнута в timeout 180; Python subprocess имеет timeout 190, runner — timeout 300. Остальные проверки имеют timeout 15–60. .env и секреты не читались и не загружались, opt-in=1 нигде не запускался.

Временный preload `/tmp/orchestrate-fetch-planner-002/T40-1/safety.mjs` передан через NODE_OPTIONS всем дочерним Node-процессам offline/live-refusal проверок. Он регистрирует реальные module resolve событий test/*.js; отвергает импорт dotenv/Piscina/stress.worker, чтение .env, создание Worker, net connect, HTTP/UDP и global fetch. Заблокированное действие записывает BLOCKED и даёт ошибку; во всех четырёх trace отсутствует BLOCKED. Live-пробы завершились именно сообщением guard, а не отказом инструментирования. Это подтверждает отказ до загрузки Piscina, workers и сети. MockAgent offline тестов работает при установленном запрете реальных соединений.
