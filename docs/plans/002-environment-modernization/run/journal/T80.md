## Решение

Вместо sealed consumer T10 используются настоящие npm installs tarball в независимые mkdtemp consumers вне репозитория и ancestor node_modules [VERIFY, ROOT]. Альтернатива — проверки из root node_modules — не даёт доказательства отсутствия dev-only undici [ALT]. Копия для pack использует только инструменты root через symlink; consumers ссылок на root dependencies не получают. Типовая зависимость undici-types 7.3.0 опубликована напрямую; undici 7.3.0 остаётся dev-only. Публичные Fetch signatures не изменены, runtime import undici не добавлен.

Prepack вызывает только production build. Проверка сначала строит эталон из текущего src в безопасной копии, затем для каждого из pnpm/npm и absent/stale build создаёт настоящий tarball, сравнивает JS/declaration/map с эталоном побайтово и src/index.ts с текущим исходником. Копия содержит test/samples/scripts и искусственные coverage/docs probes; tar entries разрешают только package metadata, README, LICENSE, src и build/src. Секреты не читаются и не копируются; .env-пути отфильтрованы до чтения. Новый exports barrier не добавлен, name/version/main/types сохранены.

Consumers устанавливают tarball с --ignore-scripts. Независимые окружения: undici отсутствует совсем (проверяется MODULE_NOT_FOUND и отсутствие каталога); undici 7.3.0 явно установлен. У каждого отдельные alias installations TS 5.7.3 и 7.0.2 и @types/node 22.20.5. Установки разбиты по зависимости, registry retries отключены, fetch timeout 20 секунд; subprocess timeout 240 секунд. Проверки типов и runtime сеть не используют. Для JS smoke выбран локальный transport, создающий настоящий native Response: root/deep imports, GET/POST, payload и identity исходного Response. Это проверка JS, а не обещание native fetch TYPE совместимости.

Type fixtures входят в обычные typecheck/lint/format/knip. Runtime fixture использует относительные imports для анализа в root; при переносе в consumer check-package заменяет их на root package import и прежний build/src deep import. Отрицательные типовые исходники генерируются отдельно без @ts-expect-error: compiler обязан дать ровно одну ошибку в negative.ts с ожидаемым кодом. Положительный fixture компилируется и отдельно, и вместе с отрицательным. Bare consumer дополнительно проверяет ровно TS2307 после временной подмены import на старый undici, затем восстанавливает декларацию в finally. Все mkdtemp directories удаляются в finally; сравнение SHA256 выбранных входов до/после запрещает изменения исходников/config/manifest/lock/README.
