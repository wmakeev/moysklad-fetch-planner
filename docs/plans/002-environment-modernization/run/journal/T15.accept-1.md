## Краевые пути и мутационные пробы

1. Node API: assert.ok/assert.throws и базовый fs.globSync реально исполнились на закреплённом Node. Стабилизация globSync с 24.0.0 подтверждена [официальной историей Node](https://nodejs.org/docs/latest-v24.x/api/fs.html#fsglobsyncpattern-options). Опции 24.1/24.16 и самый ранний runtime 24.0.0 не испытывались, что честно оговорено в исследовании. Вживую API МойСклад не проверялось: запрещено заданием и не относится к Node floor.
2. Статические отрицательные fixtures: отсутствующий относительный import/require, транзитивный semver, dev-only undici, bin вне files, отсутствие shebang, deprecated SlowBuffer и process.exit. ESLint выявил каждое соответствующим n/* правилом. Ни опасный process.exit, ни отсутствующие импорты не исполнялись.
3. Dormant process.exit типизируется TS7 strict/skipLibCheck=false и проходит oxlint; безопасный вызов dormant() проходит runtime smoke. Следовательно, types/smoke не исключают опасную неисполненную ветвь. В копии config добавлено единственное no-restricted-properties: прежний exit 0 стал ожидаемым exit 1 с нужным правилом. Это узкая альтернатива внутри oxlint, без внедрения её в проект.
4. SlowBuffer компилируется, но oxlint typescript/no-deprecated его диагностирует. Поэтому нельзя объявлять все deprecated-проверки потерянными; полное тождество покрытия JSDoc и Node-таблиц не доказано.
5. JS guard: настоящий emitted src/index.js обработан стандартным Espree и активными правилами n/*; Node diagnostics отсутствуют, TS5 parser/type service не загружались. Отрицательные JS fixtures этим же API обнаружены. Самый первый запуск с filename вне cwd ESLint ничего не анализировал; cwd исправлен, диагностики подтверждены повторно. Нулевой анализ не использовался как доказательство.
6. При буквальной проверке emit только с Node plugin остаются ссылки на TS ESLint directives: неизвестное @typescript-eslint/no-empty-function даёт configuration diagnostic. При noInlineConfig=true остаются два предупреждения о неработающих исходных директивах, но нет Node errors. Это не готовый pipeline: будущее решение должно явно обработать перенос/удаление директив в проверочной копии либо предоставить нужные определения. Наличие этой работы согласуется с оговоркой evidence/node24-floor.md:48; отдельный guard в T15 не требовался.
7. Первая дополнительная oxlint-проба imports запускалась из корня и не нашла tsgolint по cwd. Повтор из временного fixture с symlink на установленный toolchain завершился успешно и обработал 3 файла; установки/изменения проекта не потребовались. TS7 дополнительно перепроверен явно через закреплённый Node, а не shebang системного Node.

## Замечания к продолжению

Минимальный выбор: сохранить полезные Node/dependency проверки отдельным guard либо оставить один oxlint с точным запретом process.exit и явно принять остаточные потери. Рекомендован JS guard при сохранении принятого A5: цена — ESLint/plugin-n, отдельный шаг после emit, актуализация API-таблиц, обработка директив и согласование package paths. TS5 parser для него не обязателен. Это предложение владельцу, не разрешение внедрять второй pipeline.

При одном oxlint прежде всего теряются статические проверки транзитивных/непубликуемых зависимостей и версия Node API в неисполненных ветвях; deprecated покрывается частично, bin/hashbang сейчас неактуальны, process-exit-as-throw уже не работал. no-restricted-properties закрывает проверенную форму process.exit, но не доказан как полный эквивалент всех способов доступа.

Обязательный T80 реально закрывает замыкание деклараций без dev-only undici, актуальность JS после pack, наличие путей/файлов и работоспособность корневого/deep import и GET/POST на локальном transport в независимом consumer. Он обнаружит отсутствующую runtime-зависимость на исполняемом/импортируемом пути, но не гарантирует аудит всех imports: транзитивный hoisting может существовать и у consumer, а dormant dynamic import/require не выполняется smoke. T80 не заменяет статический запрет process.exit, все deprecated APIs, version guard или будущий bin/shebang. Не следует приравнивать новый floor к отказу от этих правил.
