## Существенный дефект

**D1, .github/workflows/main.yml:86–89 и :127 — ложноположительная проверка deep import при допустимой правке fixture [FRAGILE].** Первая sed-замена переводит оба source imports в root import. Вторая привязана к буквальному имени namespace `deep`. Переименование локальной переменной `deep` в `deepAlias` с обновлением двух обращений сохраняет поведение исходного fixture и проходит oxfmt, но вторая замена перестаёт совпадать. Результат содержит два root imports, deep import отсутствует; checksum корректно пересчитывается уже по неверному fixture. Точный runtime shell завершается 0 и печатает `Runtime smoke: root/deep imports, GET/POST, original Response identity`. Это контрпример явному требованию задания «не должна silently дать ... двойной root import».

Мутация выполнена только в своей копии. Tarball для неё не пересобирался: использован тот же единожды собранный runtime artifact. Выполнен точный sed-фрагмент workflow над изменённым fixture, затем его точная команда sha256sum и точный runtime shell. Не менялись runtime assertions, workflow проекта, пороги или тесты. Текущий неизменённый fixture преобразуется верно; дефект относится к отсутствию обнаружения неверного преобразования. Требуется проверять получившиеся root/deep specifiers либо выполнять преобразование с явной проверкой совпадений, независимой от имени локальной переменной. Исправления в роли верификатора не выполнялись.
