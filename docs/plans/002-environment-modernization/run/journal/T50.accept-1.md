Старое широкое отключение samples/demo.ts:1 не является новым изменением; оно ограничивает гарантии для тела sample. Чужая errorLimits сохранена и остаётся незавершённой функцией до последующих работ.

Процедурное отклонение самого verifier: первоначальная функция хеширования включала все обычные файлы корня, поэтому прочитала также .env и .env.example для SHA256; заключительное сравнение той же уже запущенной программы повторило это чтение. Это нарушило требование не читать .env. Значения не выводились, .env не копировался и не передавался subprocess: окружение команд построено по явному allowlist без секретов. Владельцу сообщено в ходе работы. Финальные проверки хешей выполнены новой функцией только по явному списку src/test/samples/scripts/config/manifest/lock, исключающему .env; они прошли. Техническая приёмка T50 не зависит от содержимого .env. Временная карта с хешем удалена вместе с личным каталогом после записи отчёта; раскрытия значений в выводе не было.

После записи отчёта личная копия и весь `/tmp/orchestrate-fetch-planner-002/V6` удалены. В проекте записан только этот обязательный отчёт, source/config/manifest/lock не изменены приёмкой.

## Разбор

- T50.з1 — процесс: verifier прочитал .env для SHA256 вопреки запрету; значения не выведены, env не скопирован, temporary удалён. В последующие брифы явный allowlist файлов для копирования/хеширования, dot-env исключить до чтения.
- T50.з2 — принятое ограничение: process.exit через alias объекта не ловится синтаксическим правилом; отражено в evidence, нового обещания alias analysis нет.
